## **이 방식의 핵심 2가지**

1. **평소엔 모듈 나눠 각자** — 파일 안 겹쳐서 빠르고 충돌 없음. 막히면 페어가 옆에서 봄.
2. **오케스트레이터(D8~9)만 둘이 뭉침** — 심장이라 같이. 여기서 지식이 두 명에게 다 쌓여서 리허설·Q&A·결선까지 안전.

## **D4에 딱 하나 먼저 합의 (제일 중요)**

**도구 함수 인터페이스(입출력)를 종이 한 장으로 동결** — 이게 "7/11 API 계약 동결"의 실체예요:

```
collect(company_id)        -> [{voucher_id, month, source, item, amount}]
classify(voucher)          -> {scope, category, fuel, confidence, evidence, quality_flag}
calculate(company_id)      -> {scope1, scope2, per_month[], pcaf_grade, gaps[]}
benchmark(industry, scope) -> {min, median, max}
trace(session_id)          -> [{step_type, tool_name, message, created_at}]
```

이 5개 시그니처만 D4에 못박으면, 그 뒤엔 **각자 속을 채워도 서로 안 부딪혀요.** 오케스트레이터도 이 시그니처에만 의존하니 페어로 붙기 쉽고요.

## 0. 버전 로드맵 — 데모에서 결선까지 한 몸

```
v0.1 (데모, 7/20)                          v1.0 (결선, 8월 말)
─────────────────────────                  ─────────────────────────
오케스트레이터 [도구 4개 등록]        →     + 도구 2개 추가 (HITL 연계, 리포트·알림)
시나리오: 결손 감지 1개               →     + 이상치 재검증, 등급 역산, 금융 연결
LLM 캐시 레이어 (적중률 100% 상태)    →     캐시 + 라이브 혼용 (동일 코드)
트레이스 녹화·재생 모드               →     그대로 = 결선 오프라인 방탄 장치
합성 전표 50건                        →     300건 (생성기 파라미터만 변경)
PCAF 수치: 시연 기업 계산치           →     2트랙 검증치로 DB 숫자만 갱신
4장면 (사장님 화면 중심)              →     + 관리자 대시보드, 벤치마킹 화면
```

- **오케스트레이터는 처음부터 정식 구조(도구 등록형)로 제작.** "미니 에이전트" 같은 별도 개념 없음 — 데모 시점에 등록된 도구가 4개일 뿐이고, 8월엔 도구를 꽂기만 함.
- **LLM 캐시는 임시방편이 아니라 정식 기능**: "동일 전표 텍스트 → 동일 응답"은 실서비스에서도 비용·재현성을 위해 필요한 레이어. 데모는 시연 전표를 사전 호출해 캐시가 100% 적중하는 상태일 뿐.
- **재생 모드도 정식 기능**: 결선장 네트워크 장애 대비책이 원래 이것 — 데모 때 만든 게 그대로 결선 방탄이 됨.

## 1. 데모에 포함되는 AI (팀 공유 — Q&A 답변 기준)

**실제로 돌아가는 AI 2개:**

| AI                                        | 하는 일                                                                                                                                                                       | 장면 |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| **① 전표 분류 AI** (Claude)               | "지게차 경유 외 1종" → Scope 1·이동연소·경유 + 근거 문장(evidence) + confidence. 캐시를 통과하지만**캐시 내용물은 Claude의 실제 분석 결과** (대본 아님)                       | ③    |
| **② 오케스트레이터 AI** (Claude tool use) | "이 기업을 측정하라"는 목표를 받고 도구 4개를 스스로 골라 호출.**3~5월 가스 전표 결손을 발견 → 사장 알림 + 업종 평균 보정 결정.** 시연은 실제 실행의 녹화 재생, 라이브는 백업 | ②    |

**AI가 아닌 것 (설계상 의도):** 탄소량 계산 = 결정론적 파이썬 코드 (LLM 산수 금지) / 최종 확정 = 사람 (HITL, 데모에선 뱃지로 표시)

**데모에 없는 AI 행동 (8월에 '추가'):** 이상치 자가 검증, 등급 상승 역산, 금융 연결 실행

> Q&A 한 문장: "데모에는 '읽는 AI'(분류)와 '판단하는 AI'(에이전트)가 둘 다 실물로 들어가 있고, 8월에는 이 에이전트에게 할 줄 아는 행동을 3개 더 가르칩니다."

### Supabase 운영 규칙

- 순수 PG로만 (Auth·Storage·자동 REST 금지). 예외: 장면 ② Realtime 구독만 선택 허용 (30분 룰 — 안 되면 2초 폴링)
- Session 풀러 + `pool_size=5, pool_pre_ping=True` / `.env` 관리, 키 커밋 금지
- **무료 티어 자동 pause 주의**: 핑 Actions(1일 1회) + 시연·심사 전날 기동 확인
- 클라우드 DB = 오프라인 불가 → **재생 모드 + 녹화 영상**이 방탄
