## 0. 착수 전 확인된 사실 — 두 전제가 비어 있다

CLAUDE.md §4 원안:

| 트랙 | 방법 | 전제 데이터 |
| --- | --- | --- |
| 트랙 A | 매출액·업종만 입력하는 기존 추정(PCAF 5등급) vs 공시 실측치 비교 | **배출량 실측 공시 기업 N개** (환경정보공개시스템 등에서 매출액·업종·공시배출량 확보) |
| 트랙 B | 분류 정확도(합성전표 300건 정답지 대조) + 물량 추정(**실물 파일럿** 전기 고지서 실측 kWh 대조) | 실측 kWh를 받을 수 있는 파일럿 협조 기업 |

이번 세션에서 사용자에게 직접 확인한 결과:

- **트랙 A의 공시 기업 리스트업 — 회계 담당 확인 필요.** 이 세션에서는
  확정할 수 없음.

즉 3수치 중 실제로 지금 바로 계산 가능한 것은 **분류 정확도 하나뿐**이다

데이터가 없어 코드를 먼저 짜는 게 무의미하다 — 회계 담당의 확인/섭외가
선행돼야 한다.

## 1. 분류 정확도 — 지금 바로 착수 가능

**입력 데이터 (이미 존재, 확인 완료):**

- `data/합성전표_300건.csv` — `db/synth_dataset_generator.py --count 300
  --companies 9 --from-excel --seed 42`로 생성. 9개 기업, DB에는 미적재
  (파일만 있음, `docs/synthetic-data-status.md` §②).
- `data/감탄_데이터준비_샘플.xlsx`의 `기대_결과` 시트 — 50건 정답지
  (`record_id`, `expected_scope`, `expected_carbon_category`,
  `expected_activity_amount`, `expected_hitl_required` 등 14개 필드,
  `db/synth_dataset_generator.py::sheet_expected_results()`가 생성 소스).

**정확도의 정의를 먼저 못박아야 한다** — "정확도 Y%"라는 한 숫자로 뭉치면
안 되는 이유: 정답지에는 Scope 판별, 연료 분류, 물량 추정(있는 경우),
HITL 회부 판단이 섞여 있다. 이 문서가 제안하는 분해:

1. **Scope/연료 분류 정확도** — `expected_scope`·`expected_carbon_category`
   와 파이프라인 출력(`Classification.scope`, `.category`, `.fuel_type`)
   비교. 자동확정(`auto`) 건만 볼지, HITL로 넘어간 건도 포함할지 미리
   정해야 함 — 제안: **자동확정 건은 정확도, 전체 건은 "자동확정 비율 +
   그중 정확도"로 분리 표기** (HITL로 넘어간 건은 "맞고 틀리고"가 아니라
   "정상적으로 사람에게 넘어갔는가"의 문제라 같은 분모에 섞으면 왜곡됨).
2. **HITL 회부 정확도** — `expected_hitl_required`(Y/N)와 실제
   `status == 'review_required'` 여부의 confusion matrix(정밀도/재현율).
   특히 **재현율이 핵심 방어 지표** — "애매한 걸 놓치지 않고 사람에게
   넘겼는가"가 금융 AI 가이드라인 보조수단성 원칙의 근거이므로, 재현율이
   낮으면(놓친 건이 많으면) 발표에서 오히려 불리한 숫자가 됨. 낮게
   나오더라도 숨기지 말고 원인 분해까지 함께 보고할 것(실패 가시성 원칙,
   CLAUDE.md §6).
3. **물량 추정 정확도** — `expected_activity_amount`가 있는 건만 대상
   (정답지에 물량이 없는 항목—제외 대상·HITL 대상—은 애초에 비교 불가).
   금액 역산 로직(`db/calc_engine.py`)이 월별 단가로 되짚은 물량과
   정답지 물량의 오차율.

**작업 항목:**

- [ ] `data/합성전표_300건.csv` 300건을 DB에 적재할지, 아니면 별도
  스크립트로 파이프라인 함수를 직접 호출(DB 미경유)할지 결정. 제안:
  기존 `vouchers`(시연용 33건)와 섞이면 트레이스 뷰·HITL 큐 등 다른 화면
  집계가 오염되므로, **별도 회사/기관으로 격리해서 적재**하거나 DB를
  거치지 않고 `api/agent/rules.py` + LLM 분류 함수를 스크립트에서 직접
  호출하는 쪽을 권장(후자가 회귀 위험 더 적음).
- [ ] 정답지(50건, `기대_결과` 시트)와 강건성 전표(300건, 정답지 없음—
  분류 규칙표 자체가 정답 소스)의 역할이 다름을 확인. 300건은
  `db/synth_dataset_generator.py --from-excel`이 `분류_기준표_확장` 58행
  룰로 라벨링한 것이라 "룰 엔진이 스스로 만든 정답과 룰 엔진 출력을
  비교"하는 순환이 될 수 있음 — **50건 정답지(사람이 직접 작성)만
  분류 정확도의 근거로 쓰고, 300건은 "강건성(문구 변형에도 안 깨지는가)"
  용도로 분리 보고**할 것. 이 구분을 발표 자료에서도 명시해야 순환논리
  지적을 피함.
- [ ] `scripts/` 아래 채점 스크립트 신규 작성 (예:
  `scripts/score_classification_accuracy.py`) — 정답지 50건을 읽어
  파이프라인 실행 → 위 1~3 지표 산출 → CSV/표로 출력. 이미 있는
  `scripts/warm_cache.py`, `scripts/extend_data_sample.py` 옆에 위치.
- [ ] 저신뢰(`confidence` 임계값 미달) 건이 실제로 몇 %인지도 같이
  보고 — LLM 호출 비율 자체가 "룰이 먼저 걸러낸다"는 설계 원칙의
  방증 수치라 발표에 같이 쓸 수 있음(원칙 3).

## 2. 트랙 A (MAPE) — 회계 담당 확인 선행 필요

**막힌 지점**: "배출량 실측 공시 기업 N개"가 리스트업됐는지 이번 세션에서
확정 못함(§0). 아래 두 갈래로 갈린다.

### 갈래 A-1: 리스트업이 이미 돼 있는 경우

- [ ] 회계 담당에게 기업 리스트 + 공시배출량 + 매출액·업종 데이터 위치
  확인 (환경정보공개시스템 `env-info.kr`, GIR 명세서가 CLAUDE.md §4 명시
  출처).
- [ ] 기존 방식 재현: 매출액·업종만으로 PCAF 5등급 통계 원단위 대입
  (`db/pcaf.py` 또는 `db/pcaf_quality.py`에 이미 있는 업종 평균 로직
  재사용 가능한지 확인 — 없으면 신규 함수 필요).
- [ ] MAPE = mean(|추정치 − 공시실측치| / 공시실측치) 계산 스크립트
  작성. N이 작을 수 있으므로(공시 기업 자체가 적음) 개별 기업별 오차도
  같이 표로 보고(평균 하나로 뭉개면 이상치에 흔들리는 숫자로 보일 위험).
- [ ] CLAUDE.md §4가 이미 명시한 한계 — "공시 기업은 중견급 이상, 타깃
  (영세)과 규모 차이" — 를 발표 자료 문구에 그대로 반영.

### 갈래 A-2: 리스트업이 안 돼 있는 경우 (현재 유력)

- [ ] **먼저 회계 담당에게 확인**: 리스트업 여부, 안 돼 있으면 착수
  가능 여부·소요기간.
- [ ] 안 되면 축소 대안 검토 — 예: 공시 기업 수를 줄여서라도(N=3~5) 최소
  표본 확보, 또는 업종 평균만으로 트랙 A를 "정성적 한계 설명"으로
  대체하고 정량 MAPE는 결선 발표에서 "진행 중" 표기. **트랙 A 자체를
  스킵하는 옵션은 CLAUDE.md §4의 핵심 방어 논리("기존 방식 오차의 정량
  공개")를 잃는 것이므로 최후 수단으로만 고려.**
- [ ] 일정 리스크로 `docs/v1-plan.md` §8 표에 이미 있는 "검증 3수치
  지연 → 병행 가능한 부분부터 진행"이 이 갈래에 해당함을 재확인.

## 3. 트랙 B — 실물대조 오차: 대체안 필요 (파일럿 미섭외)

**막힌 지점**: 실물 파일럿 기업이 없다는 것을 이번 세션에서 확인(§0).
분류 정확도(§1)는 트랙 B의 다른 절반이라 별도로 진행 가능하지만, "물량
추정을 실측과 대조"하는 절반은 대체가 필요하다.

**검토할 대체안 (택1 또는 조합, 회계·팀 논의 필요):**

1. **자체 실측 대조로 축소**: 팀 내부 인원 또는 팀 사무실의 실제 전기
   고지서 kWh를 감탄 파이프라인에 태워 오차 확인. N=1이라 통계적
   설득력은 약하지만 "허수 아님"을 보여주는 최소 증거는 됨. 발표에서
   "정식 실물 검증은 파일럿 확보 후 후속"이라고 정직하게 스코프를
   한정.
2. **공개 데이터의 검침값 대조**: 한국전력 등이 공개하는 표준 요금표·
   사용량 구간 자료와, `기대_결과` 시트의 ELEC001~004(전기고지서
   mock, 실사용량 3000/2800/2100/5200 kWh)를 비교하는 방식 — 다만
   이건 "실물"이 아니라 "생성 시 이미 알고 있던 값 재확인"이라 순환
   논리 위험이 §1의 300건과 동일하게 있음. 대외 발표 시 "실물"이라고
   부르면 안 되고 "합성 데이터 자체 정합성 확인"으로 정직하게
   표기해야 함.
3. **항등식 검증만 명시하고 트랙 B를 분류 정확도로 한정**: CLAUDE.md
   §4가 이미 "에너지 사용량 공시치를 입력으로 쓰면 배출량=사용량×계수의
   항등식 검증이 되므로 트랙을 분리해 정직하게 명시한다"고 밝힌 원칙과
   같은 결 — 실물 파일럿이 끝내 안 되면, 트랙 B는 **"분류 정확도 Y%"만
   정식 수치로 공개하고 물량 오차는 "실물 파일럿 확보 전이라 자체
   검증치 참고용"으로 격을 낮춰 표기**하는 게 안 하는 것보다 낫다 —
   원칙 5(실패를 목업으로 숨기지 않는다)와 같은 결.

**작업 항목:**

- [ ] 회계·팀 논의로 위 1~3 중 방향 결정 (지금 이 세션에서 결정하지
  않음 — 사용자 확인 필요 항목).
- [ ] 방향이 정해지면 §1의 채점 스크립트를 확장해 물량 오차 계산 추가.
- [ ] 어떤 대체안을 택하든 **발표 자료에 "왜 실물 파일럿이 아닌지"를
  선제적으로 명시** — 질문 나오기 전에 한계를 인정하는 편이
  Q&A 방어에 유리함 (CLAUDE.md §10 리스크 대응 표와 같은 태도).

## 5. 이 검증이 실제로 의미가 있는가 — 평가

결론부터: **분류 정확도는 의미 있는 수치가 나올 수 있다. 트랙 A·B는
지금 상태로 그대로 진행하면 숫자는 나오되 방어 불가능한 숫자가 될
위험이 크다.** 이유:

- **분류 정확도**: 사람이 직접 작성한 50건 정답지와 대조하므로
  순환논리가 없다. 다만 N=50은 통계적으로 작은 표본이라 "Scope
  판별 정확도 96%" 같은 단일 숫자보다, 오분류 패턴(어떤 표현에서
  틀리는지)을 같이 보여주는 게 방어력이 더 강하다 — 숫자 하나보다
  "왜 틀렸는지 아는 시스템"이 심사 배점(§0 실현가능성 30점,
  창의성 30점)에 더 잘 맞는다.
- **트랙 A**: CLAUDE.md가 이미 "기존 방식의 오차 시연"이라는 강력한
  방어 논리(§1)로 설계했지만, **공시 기업 리스트업이 안 된 채
  결선까지 가면 트랙 A 자체가 없는 셈**이 된다. 이건 발표 슬라이드
  한 줄이 아니라 심사 배점표 "실현가능성 30점"의 핵심 증거이므로,
  지금 확인이 최우선이다.
- **트랙 B 물량대조**: 실물 파일럿 없이 나온 "실물대조 오차 Z%"는
  사실이 아닌 숫자를 발표하는 것과 같다 — CLAUDE.md 원칙 5(실패를
  목업으로 숨기지 않는다)와 정면으로 충돌한다. **숫자를 만들어서
  보고하느니, 한계를 정직하게 공개하는 §3의 대체안 3번이 이 팀의
  기존 설계 철학(실패 가시성)과 더 일치한다.** "완벽한 3수치"보다
