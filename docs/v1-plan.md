## 0. v1 목표와 범위

### v1 제품 정의

> 감탄은 중소기업의 전표·고지서에서 Scope 1·2 배출량과 산정 근거를 생성하고, 비상장 중소기업 일반 목적 기업대출에 대해 PCAF 데이터 품질 후보와 금융배출량을 계산하는 시스템이다.

### v1 지원 범위

- 차주 전표·고지서 수집
- 룰·LLM 분류와 HITL
- 실제 활동자료와 금액 환산 추정의 구분
- 차주 연간 Scope 1·2 인벤토리
- Scope 3 상태 관리
- PCAF 기업대출 데이터 품질 후보
- 비상장 중소기업 일반 목적 기업대출 금융배출량
- 지원 기업대출 포트폴리오 합계·커버리지·잔액 가중 데이터 품질
- `business_loans_readiness` 체크리스트
- 결정론적 코드 판정, AI 증빙·설명 보조, 담당자 승인
- JSON·Excel 결과 내보내기

### v1 제외 범위

- 상장기업 EVIC 방식
- 부동산·PF·차량·유동화·국채 등 다른 자산군 계산
- 은행 전체 자산군의 공식 PCAF 공시 확정
- `full_pcaf_dcl` 실제 운영
- Scope 3 전체 자동산정
- 외부 assurance
- PCAF 점수 기반 우대금리 자동판정

`full_pcaf_dcl` 모드는 정본에 설계만 유지한다. v1에서는 전체 관련 자산군 데이터가 없으므로 공식 DCL 통과 여부를 출력하지 않는다.

`db/alerts.py::detect_alerts`와 `GET /admin/alerts`는 완료 상태로 유지한다. 이번 PCAF 전환에서 이상신호 알림을 다시 구현하지 않는다. 다만 화면 용어가 금융배출량 또는 PCAF 공식 등급을 잘못 암시하는지 회귀 점검한다.

## 2. 구현 원칙

1. LLM은 분류·문서 증빙 탐색·설명 초안에만 사용한다.
2. 배출량, 귀속계수, 금융배출량, 체크리스트 조건은 결정론적 코드로 계산한다.
3. AI는 PCAF 체크리스트의 `pass/fail`을 변경하지 못한다.
4. PCAF 데이터 품질 후보와 LLM confidence·HITL 상태를 분리한다.
5. 미산정 Scope·가스는 0으로 처리하지 않는다.
6. 승인 결과는 덮어쓰지 않고 새 버전으로 재산정한다.
7. 다른 금융기관의 데이터에 접근할 수 없어야 한다.
8. 실패를 목업으로 숨기지 않고 오류·검토필요 상태로 표시한다.

### 기존 이상신호 알림 보존 검증

pull에서 완료된 다음 세부 구현을 그대로 유지한다.

| 구현 | 보존 검증 |
|---|---|
| `db/alerts.py::detect_alerts`의 최근 3개월 이동평균 대비 급등·급감 | 급등·급감·정상·이력부족 골든 케이스 유지 |
| 마지막 보고월 이후 3개월 이상 연속 공백 감지 | 공백 알림 골든 케이스 유지 |
| `GET /admin/alerts`와 `GET /owner/alerts/{company_id}`의 동일 판정 로직 | 은행·사장 화면 결과 정합성 확인 |
| `AlertsPanel.tsx` 실 API 연결과 공용 에러 배너 | 목업 폴백이 없는지 확인 |
| severity→기업명 정렬 | 다중 기업 정렬 회귀 테스트 |

이상치 판정 관점은 기존대로 분리한다. 오케스트레이터는 같은 연료의 평월 중앙값 대비 단일 전표 이상치를 재검증하고, `db/alerts.py`는 기업 전체 Scope 1·2 월합계의 이동평균으로 조기경보를 만든다.

`--count`가 아니라 `--companies`로 확장해야 기업당 생성 상한과 월별 패턴을 유지한다.

### 기존 2트랙 검증 보존

#### 트랙 A - 통계 추정 방식의 오차

- 실제 배출량을 공개한 제조업체 N개를 선정한다.
- 매출액·업종 기반 통계 추정값과 공개 배출량을 비교한다.
- MAPE와 기업별 오차를 계산한다.
- 이 결과를 PCAF 공식 Score 5 검증이라고 부르지 않고 `통계 추정 기준선의 오차`로 표현한다.
- 공시기업과 영세 중소기업의 규모 차이를 제한사항에 적는다.

#### 트랙 B - 감탄 엔진 검증

- 합성 전표 약 300건을 분류 정답지와 대조해 분류 정확도를 산출한다.
- 연료·전력 계수 매핑 정확도를 별도로 산출한다.
- 실물 파일럿 고지서의 실제 kWh·L·Nm3와 감탄 추출값을 비교한다.
- 금액 환산 자료는 실제 사용량이 아니므로 실물 고지서 검증과 분리한다.
- 오분류 케이스 리포트를 생성해 룰북 보강 후 한 번 재측정한다.

### 검증 자동화 산출물

- 분류 정확도
- 계수 매핑 정확도
- 트랙 A MAPE
- 실물 사용량 추출 오차
- 오분류 목록과 적용 룰
- 데이터 방법별 표본 수

### 2주차 완료조건

- 기업·연도·Scope별 인벤토리가 생성된다.
- 실제·추정·산업평균 자료 구성비와 완전성이 표시된다.
- 모든 품질 후보에 PCAF 규칙 코드와 증빙 근거가 있다.
- LLM confidence·HITL·완전성·PCAF 품질 후보가 별도 필드다.
- 미산정 Scope 3와 미확인 가스가 0으로 합산되지 않는다.
- 합성 전표 약 300건과 8~10개 기업 데이터가 생성된다.
- 분류 정확도·계수 매핑·트랙 A MAPE·실물 대조 오차가 재현 가능한 스크립트로 산출된다.
- 정확도가 목표에 미달하면 검증된 사례 중심으로 시연 데이터를 재구성하고 그 사실을 기록한다.

| 3 | 조직경계와 재무 연결범위 검사 | 불일치 시 `review_required` |

| 5 | 중복·복수대출·공동대출·귀속계수 100% 초과 처리 | 임의 cap 금지 테스트 |

산식:

```text
분모 = 총자본 + PCAF 방법론상 total debt
귀속계수 = 대출잔액 / 분모
금융배출량 = 귀속계수 × 차주 배출량
```

| 순서 | 작업 | 검증 |

| 3 | 포함·제외 잔액과 지원범위 커버리지 | 분모·분자·사유 테스트 |

## 7. 기존 1주차 기능 처리

### 이상신호 알림

pull 기준 완료 상태를 유지한다.

- `db/alerts.py::detect_alerts`
- `GET /admin/alerts`
- `AlertsPanel.tsx` 실 API 연결
- `tests/test_admin.py` 골든 케이스

PCAF 전환 과정에서 제거하지 않고 회귀테스트만 수행한다.

### 기존 등급 상승 역산

기존 계획의 다음 기능은 취소한다.

> PCAF 3등급에서 2등급으로 올리기 위해 필요한 고지서를 역산하고 우대금리 대상으로 안내

대체 기능:

> 실제 활동자료 비율과 인벤토리 완전성을 높이기 위해 부족한 문서·월·배출원을 안내

대체 결과 예시:

```text
현재 실제 활동자료 비율: 78%
도시가스 3월·4월 고지서 누락
자료 추가 시 예상 활동자료 비율: 86%
PCAF 데이터 품질 후보는 은행 최종 검토 필요
```

이 안내는 PCAF 점수 상승이나 우대금리 자격을 보장하지 않는다.

기존 관리자 수직 슬라이스 자체는 없애지 않고 이름과 계약을 다음처럼 바꾼다.

| 기존 구현·계획 | v1 대체 구현 | 완료 조건 |
|---|---|---|
| `RateCandidates.tsx` | `DataImprovementRequests.tsx`로 교체 | 금리 후보가 아니라 누락 데이터·증빙·산정 영향 표시 |
| `MOCK_RATE_CANDIDATES` | 제거 | 운영 화면에 하드코딩 후보 데이터가 남지 않음 |
| 등급 목표·금리 혜택 카드 | 현재 품질, 누락 항목, 개선 후 재산정 결과 카드 | 실제 입력·증빙에서 결과까지 추적 가능 |
| 후보 목록 API | `GET /admin/data-improvement-requests` | 차주별 보완 항목, 우선순위, 근거, 상태 반환 |
| 후보 승인 액션 | 보완 요청 생성·완료·재검토 액션 | 승인만으로 등급이 바뀌지 않고 데이터 변경 뒤 재평가 |

기존 알림 수직 슬라이스는 이미 구현된 실 API를 그대로 유지한다. `AlertsPanel.tsx`를 다시 mock으로 돌리지 않으며, 알림 규칙·목록·확인 상태의 회귀테스트를 추가한다.

두 관리자 카드 모두 로딩·빈 상태·다건·API 오류 상태를 각각 구현한다. API 오류 때 과거 mock을 대신 보여주지 않고 공용 오류 배너와 재시도 동작을 제공한다. 알림 임계값을 조정할 때는 급등·급감·정상·이력부족·공백 골든 케이스와 회계·도메인 검수를 함께 갱신한다.

## 10. v1 완료 정의

1. 차주 자체 Scope 1·2와 은행 금융배출량이 분리된다.
2. 실제 활동자료와 추정자료가 구분된다.
3. 차주 연간 인벤토리와 완전성이 생성된다.
4. PCAF 품질 후보에 규칙·근거·제한사항이 있다.
5. 비상장 일반 목적 기업대출만 금융배출량을 계산한다.
6. 지원 포트폴리오 합계와 잔액 가중 품질이 정확하다.
7. Scope 3 미산정과 미확인 가스를 0으로 처리하지 않는다.
8. 조직경계·통화·기준일·total debt를 검증한다.
9. `business_loans_readiness`가 코드 판정·AI 보조·담당자 승인으로 동작한다.
10. 다른 금융기관 데이터에 접근할 수 없다.
11. 승인 결과와 산정 입력을 재현할 수 있다.
12. 기존 이상신호 알림·분류·HITL이 정상 동작한다.
13. 활성 문서와 화면에서 공식 PCAF 등급·우대금리 보장·전체 DCL 통과를 주장하지 않는다.
14. 최소 300건, 8~10개 기업의 합성 거래 데이터로 분류·배출량·다기업 포트폴리오 화면을 검증한다.
15. 활동자료가 있는 Track A에서는 기존 MAPE 비교를 유지하되 공식 PCAF 품질등급과 분리된 성능 지표로 표시한다.
16. 300건 수작업 라벨과 실제 공공요금 청구서 샘플로 분류 정확도, 배출계수 매핑 정확도, 배출량 오차를 기록한다.
17. 분류 정확도가 90% 미만이거나 반복 오분류 패턴이 발견되면 `misclassification_report`를 남기고 개선 항목을 백로그에 연결한다.

## 12. 브랜치·병합 원칙

- 기준 브랜치는 `dev`다.
- 신규 작업은 `codex/` 또는 팀 합의 기능 브랜치에서 진행한다.
- 공용 스키마 migration은 순서를 합의하고 한 명이 작성한다.
- 다른 사람의 미완료 변경을 덮어쓰지 않는다.
- `dev → main`은 전체 테스트·문서 정합성·통주 시연 이후 한 번만 수행한다.
- 기능 동결 이후에는 범위 확장 없이 결함 수정만 허용한다.
