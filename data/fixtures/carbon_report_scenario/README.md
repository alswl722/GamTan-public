# 탄소리포트 시연 fixture — ○○정밀 2026년 1~12월

```text
Status: synthetic-data
Generated by: scripts/generate_carbon_report_scenario_fixtures.py
Renderer: Chrome headless --print-to-pdf
Company: ○○정밀 (금속가공 2차 벤더, 12명, 경북 구미)
Period: 2026-01 ~ 2026-12
```

현행 `extract_pdf_text` → `parse_document_text` 텍스트 경로와 결정론 분류 룰,
이상치 detector를 한 회사·1년치 문서로 시연하는 standalone fixture다. 실제 PDF는
**47개**(경유 세금계산서 24 + 전기 12 + 도시가스 9 + 친환경 설비 세금계산서 1 +
용접가스 세금계산서 1)이며, `_manifest.csv`에는 이 47행과 도시가스 결손 3행을 합쳐
**50행**이 있다.

도시가스 3·4·5월분은 의도적으로 파일을 만들지 않는다. 생성기는 실행할 때 출력
디렉터리의 기존 PDF를 연도와 무관하게 모두 삭제하고 다시 만들며, 가스 누적 지침도
초기화하므로 같은 프로세스에서 반복 실행해도 결정론적이다.

## manifest 금액·단위 기준

`_manifest.csv`는 PDF에 인쇄된 값을 현행 parser가 반환하는 의미에 맞춘다.

- **세금계산서(경유·설비·용접가스)**: `supply_amount_krw`는 부가세 전 **공급가액**이다.
- **전기·도시가스 고지서**: `supply_amount_krw`는 parser가 `청구금액`에서 읽는
  **VAT 포함 최종 청구금액**이다.
- 전기·가스의 `issue_date`는 parser 계약에 맞춰 해당 사용월 말일이다.
- 별지 제11호 세금계산서의 수량 칸에는 단위가 별도로 인쇄되지 않으므로 parser도
  `quantity_unit`을 만들지 않는다. 이에 맞춰 해당 manifest 행의 `unit`은 비워 둔다.
- 8월 추정 전기는 quantity와 unit이 모두 비어 있다. 나머지 전기 11건과 가스 9건은
  각각 `kWh`, `m3` 수량이 정확히 들어 있다.
- 가스 parser가 공급자·품목을 정규화해 반환하는 계약에 따라 정상 가스 행의
  `supplier`와 `item`은 모두 `도시가스`다. PDF에는 실제 발행 사업자 `대성에너지`도
  별도로 표시된다.

만들지 않는다.

## 파서용 문서 계약

- 정상 전기 11건에는 `사용량(kWh): N` 인라인 라벨을 넣어 quantity를 직접 읽게 한다.
- 8월 전기는 문서 전체에서 parser가 잡을 수 있는 숫자+`kWh` 토큰을 제거했다.
- 가스 9건에는 `사용량(m³): N` 인라인 라벨을 넣어 quantity 누락을 막았다.
- 세금계산서에는 parser가 공급자까지 manifest와 맞출 수 있도록 `공급자: 상호` 메타
  라인을 별도로 둔다.
- 모든 파일명, 문서의 사용·작성·발행·납기 날짜, manifest 월은 2026년 안에 있다.
  12월 고지서의 다음 달 발행·납기 표시는 연도를 넘기지 않도록 12월 31일로 고정한다.

## 재생성

저장소 루트에서 실행한다.

```bash
.venv/bin/python -m scripts.generate_carbon_report_scenario_fixtures
```

Chrome 또는 Chromium이 필요하다. 생성 결과는 항상 PDF 47개, manifest 50행,
결손월 `[3, 4, 5]`여야 한다.
